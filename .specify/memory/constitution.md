# 建筑智能项目宪章

## 核心原则

### 一、MVP 演示范围优先

本项目是复杂项目的 MVP 演示实现。必须围绕给定需求快速交付可演示结果，
只实现当前需求明确要求的功能，不提前建设完整产品能力，不为未来需求预留架构。
规范、计划和任务必须以当前演示范围为边界。

### 二、核心路径正确

必须确保需求定义的核心用户路径能够完成，关键操作、数据流转和结果展示必须符合需求。
优先解决阻断核心路径的问题，不将非核心边界情况扩展为额外开发范围。
通过针对实际流程的必要人工走查确认核心路径正确性，无需编写自动化测试。

### 三、直接简单实现

必须采用满足当前需求的最直接实现，避免过度抽象和防御性编程。
不为可拓展性增加通用框架、插件机制、额外分层或配置系统；仅在当前代码确有需要时提取复用。
校验和错误处理限于核心路径正确运行及现有项目约定所需的部分。

### 四、最小验收门槛

功能交付以核心路径正确、静态代码检查通过为验收门槛。
必须通过现有代码规范与类型检查，不得跳过提交钩子。
无需编写测试，不要求测试覆盖率；无需考虑无障碍，不将无障碍设计、适配或审计纳入任务和验收。
不得因通用模板的默认要求追加这些工作。

### 五、中文文档

所有新建或修改的项目文档必须使用中文，包括需求规范、计划、任务、说明和交付记录。
代码标识符、命令、路径和必要技术专有名词可以保留原文。
上游工具自带的技能与模板保留原文，基于模板生成的项目文档必须使用中文。

## 实现约束

- 使用现有 npm、Next.js App Router、TypeScript、Tailwind CSS、Biome、shadcn/ui 和
  lucide-react 技术栈，沿用现有目录、导入和组件约定。
- 具体开发约定和外部文档查阅流程遵循项目 `AGENTS.md`，只查询当前任务需要的资料。
- 沿用现有密钥管理、服务端边界和数据权限约定，不以 MVP 简化为由破坏这些约定。
- 不处理 `npm audit`，不引入与当前需求无关的架构优化、生产化建设或额外质量流程。

## 开发与验收流程

1. 优先使用 Spec Kit 明确需求、核心路径、计划和任务，文档详略以支持直接实现为准。
2. 只拆分完成当前需求所需的任务，不生成测试、可拓展性或无障碍专项任务。
3. 按核心路径优先的顺序实现，使用现有组件和工具，避免无关重构。
4. 对核心路径进行必要的人工走查，运行 `npm run check` 完成代码规范和类型检查。
5. 修复阻断核心路径及静态检查的问题后即可交付，说明完成范围与已知限制。
   构建、部署等操作仅在当前需求明确需要时纳入任务，不追加为默认验收门槛。

## 治理

本宪章约束项目的规范、计划、任务和实现审查。通用模板中的测试、可拓展性和无障碍要求
必须按本项目 MVP 原则裁剪，不得自动升级为交付门槛。
用户后续明确指令优先，现有项目开发约定中仍适用的细节继续遵循。

修订必须记录变更内容、原因、版本和修订日期；项目负责人通过明确指令确认规则变化后更新宪章。
版本采用语义化版本：删除或重新定义原则等不兼容变更增加主版本；
新增原则或实质扩充规则增加次版本；措辞澄清和勘误增加修订版本。
首次正式制定使用 1.0.0。

每次规范、计划、任务及交付审查必须确认范围聚焦、实现简单、核心路径正确、静态检查通过，
并确认项目文档使用中文。发现冲突时按用户明确要求及本宪章调整当前工作，
无需为治理检查增加独立测试或额外交付流程。
