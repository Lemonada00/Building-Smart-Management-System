# 启动与人工验证指南

本指南为实现后执行的验收步骤，不表示当前功能已经实现或通过验收。字段与接口见 [data-model.md](data-model.md) 和 [读取契约](contracts/read-contract.md)。

## 前提与运行

1. 沿用现有 Supabase 项目，准备忽略的 .env.local：公开 URL/Publishable Key 用于应用，SUPABASE_SECRET_KEY 仅离线 seed:demo 使用。不得输出或提交密钥及账号密码。
2. 新环境在仓库根目录执行 npm ci。实现人员先核对当前云端结构及迁移历史，确认未重复应用迁移；实施迁移须使用实际可用 CLI 的 --help 确认命令并生成迁移名，或使用连接器 apply_migration 将已审阅迁移应用至约定云项目。不得把本指南当作已执行迁移。
3. 迁移后检查两表 RLS、显式 SELECT 授权、函数权限和固定 search_path；重新读取云端验证结构，检查数据库安全建议，处理本次变更引入的问题。
4. 执行 npm run seed:demo。预期账号密码保持不变，准备 16 张固定模拟工单与六类记录，生成 .local/demo-work-orders.json 验收清单；再执行一次，编号、工单数、记录数及账号不重复。第二项目为 multi001 增加施工身份，角色关系总数预期为 9。
5. 执行 npm run dev，访问 http://127.0.0.1:3000/login。登录凭据从 .local/demo-accounts.json 本地读取，不写入验收文档。
6. 最终执行 npm run check，记录结果；只有实现或当前任务明确需要时才构建或部署。

## 1. 列表与六种组合（SC-002）

分别用 qc001 质检身份、sg001 施工身份查看 /work-orders：

- 默认待处理、最新优先，摘要分别为我提出的、我负责的，均限定当前项目。
- 顺序走查 pending/newest、pending/oldest、ended/newest、ended/oldest、all/newest、all/oldest，对照样本清单逐条核对编号、状态、责任人和专业。
- 已结束只含 completed/rejected；所有结果中 urgent 在前且红框高亮，其他严重程度不参与排序；同创建时间按编号同向稳定排序。
- 在列表找到指定可见工单，核对责任人、位置与最新记录，整条路径在 1 分钟内完成。

## 2. 完整详情与记录（SC-003）

- 各打开一张待处理、已完成、已拒绝工单，核对所有基础信息、问题字段、归因与建议，空值明确显示。
- 按样本检查六类记录，时间倒序、同时间稳定；状态、人员和编辑字段均有前后值。
- 核对解决→重开样本：当前归因/建议为空，历史解决内容仍完整；再次解决样本当前显示新结果，第一次结果仍存在；拒绝→重开样本仍能回看拒绝原因。
- 无图片样本正常显示，不出现假上传、假处理按钮或公开图片绕过权限。

## 3. 当前身份隔离（SC-001）

| 身份或情况 | 必须看到或拒绝的结果 |
| --- | --- |
| qc001 / A质检员 | 只看自己发起，不能读取其他发起人的详情和记录 |
| sg001 / A施工方 | 只看当前负责；已转派给 sg002 的样本在列表、直链、GET 和表读取均失权 |
| admin001 / A管理员 | 可直链读 A 全部工单；不可读 B；普通列表入口无权限 |
| multi001 / A施工方 | 本人发起但由他人负责的工单无权；不叠加本人质检/管理员角色 |
| multi001 / A管理员 | 可读 A，不可读 B |
| 退出重登后 multi001 / B管理员 | 可读 B，不可读 A |
| 登录但未选身份、无成员身份、未登录 | 不返回工单或记录内容 |

浏览器页面走查之外，通过当前真实会话的 Publishable Key + 用户 JWT 临时请求两表及只读 RPC，核对：

- 越权查询返回空或拒绝，不能从 records 绕过父工单授权；无权工单姓名 helper 也不返回姓名。
- 直接 INSERT/UPDATE/DELETE 两表均被拒绝，包含管理员业务账号；不要使用 service_role 验证普通用户权限。
- profiles 仍仅本人可读，工单姓名读取不变成成员目录。
- get_work_order 与 GET 对有效未知编号返回未找到，对已有无权编号返回无权限；只披露必要结果，不返回工单摘要。
- 退出后旧令牌再次请求被有效会话/身份校验挡住，撤销成员后再次读取失权。

此处是必要人工请求核对，不创建可提交自动化测试套件。临时凭据仅留忽略文件，结果只记身份、样本编号、预期/实际，不记 JWT。

## 4. 设备、返回与安全回跳（SC-004）

- 1440px 下从 ended/oldest 打开工单，右侧抽屉显示；关闭后筛选、排序与列表不变。
- 快速切换两张工单、关闭正在加载的抽屉，迟到响应不会显示错误工单或重新打开抽屉。
- 390px 下相同操作进入独立页面，返回保留 ended/oldest；页面不横向溢出，核心筛选入口可见。
- 新标签打开、粘贴详情链接、刷新详情均展示独立页面。
- 未登录直接打开合法详情，完成登录与身份选择后回到该详情；非法或外部 next 不能跳转外域。
- 详情菜单选中与当前角色匹配，管理员未新增普通列表菜单，其他未开放页面保持阶段边界。

## 5. 异常（SC-005）

- 用无匹配筛选或空样本范围核对中文空结果。
- 通过浏览器网络限速观察列表及抽屉加载反馈；暂时阻断详情请求，验证错误重试，恢复后成功。
- 不合法编号与合法不存在编号显示未找到；跨项目编号显示无权限，正文与姓名均不出现。
- 非法 status/sort 归一默认值，API 返回 JSON 错误而非登录 HTML；空可选信息不触发错误页。
