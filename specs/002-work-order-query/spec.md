## 用户场景与验收

### 用户故事 1 — 查看当前身份相关工单（优先级：P1）

质检员查看当前项目内自己发起的工单，施工方查看当前项目内自己当前负责的工单，默认优先关注待处理问题。

**优先原因**：这是工单查询的主要入口，也是后续处理闭环的基础。

**独立验收**：分别使用质检员、施工方账号登录，对照预置工单核对列表、状态筛选及排序。

**验收场景**：

1. **假设**当前身份为质检员，**当**进入工单列表，**则**默认只展示本人在当前项目发起的待处理工单，并显示当前范围摘要。
2. **假设**当前身份为施工方，**当**进入列表，**则**只展示当前由本人负责的工单；曾经负责但已转派的工单不出现。
3. **假设**有三种状态工单，**当**切换“已结束”或“全部”，**则**分别展示已完成与已拒绝的合集、或当前身份范围内所有状态工单。
4. **假设**结果含紧急与非紧急工单，**当**切换最新或最旧优先，**则**紧急始终在最前且红框高亮，每组内部按创建时间排序。

### 用户故事 2 — 查看完整详情与历史处理结果（优先级：P1）

有权限的用户查看工单基础信息、现场问题、当前周期处理信息和历史记录，理解当前处理状态及前因后果。

**优先原因**：列表摘要不足以支持现场核对和历史追踪。

**独立验收**：直接访问有权限的工单链接，核对所有信息分区及经历解决、重开和转派的历史记录。

**验收场景**：

1. **假设**工单包含完整信息，**当**打开详情，**则**展示编号、状态、严重程度、创建时间、发起人、项目、当前责任人、专业类型、问题描述、位置、问题详情、当前周期归因及预防建议。
2. **假设**工单有多次处理记录，**当**阅读记录区，**则**按时间倒序展示操作类型、操作人、时间、说明及发生的状态、责任人和字段变化。
3. **假设**工单曾解决后重新打开，**当**查看详情，**则**当前归因和建议为空，历史解决记录仍完整展示该次归因及建议；拒绝记录保留拒绝原因。
4. **假设**当前为管理员身份，**当**直接访问当前项目工单链接，**则**可查看完整详情；跨项目工单不可见。

### 用户故事 3 — 在电脑和手机上连续浏览（优先级：P2）

用户从列表打开详情并返回，保持浏览上下文；从分享链接进入时也能独立阅读。

**优先原因**：现场手机浏览和电脑浏览需要一致的工单信息及稳定返回路径。

**独立验收**：在 1440px 和 390px 宽度分别从列表打开、关闭、返回并刷新详情链接。

**验收场景**：

1. **假设**从宽屏列表点击工单，**当**详情打开，**则**以右侧抽屉展示，关闭后仍保留原状态筛选及排序。
2. **假设**从窄屏列表点击工单，**当**进入详情，**则**使用独立页面，返回列表保留原状态筛选及排序。
3. **假设**直接访问或刷新工单链接，**当**权限通过，**则**独立页面完整显示详情，并提供返回当前角色可访问页面的入口。
4. **假设**查询无结果、正在加载或失败，**当**查看页面，**则**分别看到清晰的空结果、加载过渡或可重试错误提示。

### 边界情况

- 未登录或未选身份时沿用现有登录与身份选择流程，不提前展示业务数据。
- 用户同时拥有多个项目或角色时，只按当前选定身份授权；施工方即使同时是发起人，也不能查看当前不由本人负责的工单。
- 不存在的编号展示未找到；存在但无权读取的工单显示无权限，不泄露标题、项目、参与人和处理记录。
- 不合法的工单链接显示未找到；不支持的筛选或排序值回到默认待处理、最新优先。
- 创建时间相同的工单以编号稳定排序；切换排序后紧急优先规则不变。
- 可选信息为空时明确标注未填写或暂无，不将空值误作加载失败；无记录时显示暂无处理记录。
- 列表和详情中的姓名仅用于业务展示，不暴露登录凭据或扩展为成员目录。
- 打开后权限失效或会话过期，再次读取时须重新检查，不能继续返回历史有权读取的内容。

## 需求

### 功能需求

- **FR-001**：系统必须保存工单及关联处理记录。工单编号唯一且稳定，所属项目、发起人、当前责任人和创建时间明确。
- **FR-002**：工单状态仅为待处理、已完成、已拒绝；严重程度仅为轻微、一般、严重、紧急；专业类型仅为建筑设计专业、结构专业、给排水专业。
- **FR-003**：每次列表、详情和处理记录读取必须按当前会话的唯一项目与角色授权：质检员仅本人发起，施工方仅本人当前负责，管理员仅当前项目全部工单；其他身份权限不叠加。任何普通业务用户本阶段均不能创建、修改或删除工单及记录。
- **FR-004**：普通工单列表仅面向质检员和施工方，默认待处理、最新优先；支持待处理、已结束、全部以及最新优先、最旧优先，并展示生效范围。已结束包含已完成和已拒绝。
- **FR-005**：所有普通列表结果必须紧急优先，紧急项以红框高亮；同为紧急或非紧急时按创建时间排序，同时间以编号按所选方向稳定排序。
- **FR-006**：列表项必须展示编号、状态、严重程度、问题描述摘要、详细位置、创建时间、当前责任人姓名和专业类型；长摘要可截断，完整内容可在详情读取。
- **FR-007**：详情必须按基础信息、问题信息、当前周期处理信息、处理记录分区，完整展示用户故事 2 所列字段，顶部保留编号、状态、严重程度与返回或关闭入口。
- **FR-008**：处理记录必须关联工单，保留创建、编辑、解决、拒绝、指派他人、重新打开六类操作的类型、操作人、时间、原因或说明与变更内容；展示变更前后值，按时间倒序、同时间稳定排序。解决记录保存当次归因及建议，拒绝记录保存当次原因，不因后续周期覆盖。
- **FR-009**：从列表进入详情时宽屏使用右侧抽屉，窄屏使用独立页面；直接链接始终支持独立详情页面。各入口展示相同内容并遵守相同权限，返回列表保留状态筛选和排序。
- **FR-010**：系统必须提供加载、空结果、读取失败及重试、未找到、无权限提示。无权限或未找到页面不展示受限业务信息。
- **FR-011**：演示数据必须在现有两个模拟项目内覆盖三种状态、四种严重程度、三种专业、不同发起人与至少两名责任人，并包含创建、编辑、解决、拒绝、指派和重开历史；包含重开后归因清空、历史结果保留及原责任人失权的可验证样本。数据应可重复准备，不产生重复样本或改动无关数据。
- **FR-012**：界面沿用原型的白底、浅蓝、信息层次和详情分区，使用中文，不加入渐变、发光和堆叠阴影；390px 与 1440px 下核心信息和筛选入口均可阅读使用。
- **FR-013**：本阶段仅开放读取，不提供手动建单或未实现的编辑、解决、拒绝、指派、重开操作入口。管理员可经直接链接验收当前项目读取权限，其工单中心和数据大盘仍按后续阶段安排。
- **FR-014**：现场图片为选填信息，图片访问与存储能力在阶段 3 补齐；本阶段无图片工单必须正常展示，不能以不受权限控制的图片地址充当正式图片交付。后续具备图片能力后，列表显示首张预览，详情显示全部现场图片。

### 关键实体

- **工单**：唯一编号、所属项目、状态、创建时间、发起人、当前责任人；严重程度、专业类型、问题描述、详细位置、可选现场图片与问题详情；当前处理周期的归因及预防建议。
- **处理记录**：关联工单的单次历史操作，包括操作人、类型、发生时间、原因、字段及状态或责任人变化、当次处理结果；历史结果独立于工单当前周期展示。
- **当前会话身份**：已有的用户、项目与角色组合，是所有工单和记录读取的唯一授权依据。
- **演示样本**：明确标记为模拟的工单和历史记录，关联已有项目与人员，支持重复准备及权限对照验收。

## 成功标准

### 可衡量结果

- **SC-001**：对照预置样本，三种角色的列表或直链、跨项目、多身份不叠加、原责任人失权检查全部符合权限规则，越权返回业务内容为 0 条。
- **SC-002**：普通列表的 3 种状态筛选与 2 种排序的全部 6 种组合均与样本预期一致；每种组合中紧急优先、同组时间顺序及同时间稳定排序全部正确。
- **SC-003**：每种状态至少核对 1 张详情；字段与样本一致率为 100%，六类历史记录及解决后重开样本可完整回看，历史处理结果丢失为 0 项。
- **SC-004**：390px 和 1440px 各完成一次列表筛选、打开详情、返回与直接链接访问，所有步骤通过，返回后筛选及排序丢失为 0 次。
- **SC-005**：加载、空结果、错误重试、未找到和无权限五类状态均有明确中文反馈；演示人员可在 1 分钟内从列表找到指定可见工单并核对责任人、位置及最新记录。

## 假设与依赖

- 依赖已验收的阶段 1 登录、会话身份、项目、角色和模拟账号；沿用两项目演示范围，不增加账号或成员管理。
- 需求依据为 `doc/建筑施工质检情报员规格文档.md` 第 2.2、5.2、5.3、6 节和 `progress.md` 阶段 2；分阶段边界遵循 `docs/分阶段开发与上线规划.md`。
- 视觉依据为 `design/stitch/16591807519307787618/` 中展示模式详情与通用框架原型。普通列表无单独原型，依照需求文档细化并沿用现有框架风格；原型中的后续操作不能扩大本阶段范围。
- 图片存储及编辑操作属于阶段 3，管理员工单中心属于阶段 4，自然语言查询属于阶段 5，正式建单属于阶段 6，公网部署属于阶段 7。
- 本阶段管理员通过已知样本详情链接验收读取范围，不为其添加普通列表或提前建设工单中心。
- 数据授权需同时约束工单与所属处理记录；区分无权限与不存在仅提供必要结果，不允许读取受限详情或枚举敏感信息。
- 验收采用必要人工走查，不新增自动化测试、覆盖率、无障碍专项或扩展架构任务；代码规范和类型检查遵循现有交付要求。
