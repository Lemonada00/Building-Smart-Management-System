## 用户场景与验收

### 用户故事 1 — 使用工号登录（优先级：P1）

预置账号用户通过工号和密码进入系统；只有一个项目角色身份时直接进入应用，无需额外选择。

**优先原因**：登录是所有业务访问的前提。

**独立验收**：使用单身份账号从未登录状态进入，核对登录结果和当前身份。

**验收场景**：

1. **给定**用户未登录，**当**访问受保护页面，**则**展示登录页，并保留应用内目标页面。
2. **给定**账号只有一个身份，**当**提交正确工号和密码，**则**自动确定该身份，进入有权访问的目标页面；没有目标时进入智能助手。
3. **给定**输入为空或凭据错误，**当**提交，**则**在表单附近提供中文提示，不进入应用；失败保留工号，不展示密码明文。
4. **给定**登录请求进行中，**当**再次点击登录，**则**显示进行态且不重复提交；服务失败后允许重试。

### 用户故事 2 — 选择唯一的本次身份（优先级：P1）

同一账号拥有多个项目或角色时，用户明确选择一个身份；本次使用只获得该身份的权限。

**优先原因**：防止多角色和跨项目权限混用。

**独立验收**：使用同项目多角色、跨项目多身份账号分别登录，选择不同身份，核对展示和访问范围。

**验收场景**：

1. **给定**账号有多个身份，**当**登录成功，**则**显示“选择本次登录身份”弹窗，各条目展示项目名称和角色名称。
2. **给定**尚未选择身份，**当**关闭弹窗、刷新或直接访问业务页面，**则**仍不能进入业务，继续要求选择；提供退出入口。
3. **给定**用户选择有效身份，**当**选择成功，**则**关闭弹窗并进入目标页或默认助手页，导航展示该身份。
4. **给定**当前为施工方且账号另有管理员身份，**当**访问管理员页面，**则**显示无权限说明和返回可访问页面入口，不合并管理员权限。
5. **给定**客户端提交其他用户的身份、不存在的身份或尝试在本次登录中替换已选身份，**当**处理请求，**则**拒绝操作且不改变当前权限。
6. **给定**已有有效登录和身份，**当**刷新或切换页面，**则**保留当前身份，不重复选择。

### 用户故事 3 — 按当前角色浏览应用（优先级：P2）

用户在电脑和手机中查看当前项目、角色与功能导航，清楚识别当前页面和尚未开放的能力。

**优先原因**：为后续业务提供一致入口，支持现场窄屏使用。

**独立验收**：三种角色分别在宽屏和窄屏下浏览全部菜单，并直接访问无权页面。

**验收场景**：

1. **给定**质检员或施工方身份，**当**进入应用，**则**仅展示“智能助手”和“工单列表”菜单。
2. **给定**管理员身份，**当**进入应用，**则**仅展示“智能助手”“数据大盘”和“管理员工单中心”菜单。
3. **给定**宽屏，**当**打开应用，**则**左侧显示导航、右侧显示内容，当前菜单有选中态；窄屏时内容默认全屏，导航通过菜单按钮展开。
4. **给定**窄屏菜单已展开，**当**选择菜单、点击遮罩或关闭按钮，**则**菜单关闭；选中菜单后显示对应内容。
5. **给定**用户资料有头像或没有头像，**当**查看导航身份区，**则**分别展示头像或姓名首字，同时展示姓名、部门、项目和角色。
6. **给定**当前阶段的业务入口，**当**进入助手、工单列表、大盘或管理员中心，**则**展示对应页面标题及尚未开放说明，不显示虚构工单、统计或可发送的助手。

### 用户故事 4 — 退出后重新选择身份（优先级：P2）

用户通过退出再登录切换项目或角色，确保离开后原身份不能继续使用。

**优先原因**：满足明确的身份切换规则，防止共享设备遗留访问。

**独立验收**：多身份账号选择身份后退出，回退或直访旧页面，再登录选择另一个身份。

**验收场景**：

1. **给定**用户已登录，**当**退出成功，**则**清除登录与当前身份并返回登录页；刷新、回退或再次请求受保护内容不能恢复访问。
2. **给定**多身份账号已退出，**当**重新登录，**则**重新选择身份，不自动沿用上次身份。
3. **给定**退出操作失败，**当**返回结果，**则**明确提示失败并允许重试，不误报退出成功。

### 边界情况

- 账号认证成功但没有可用身份：说明未配置可用身份，禁止进入业务并允许退出。
- 所选身份被外部撤销或关联项目失效：下次访问时停止使用该身份，提示重新登录，不自动切换到其他身份。
- 登录失效：重新登录并重新执行身份确定流程，不沿用失效身份。
- 登录前目标无权限：身份确定后显示无权限页面，不擅自提升角色；应用外目标不作为跳转地址。
- 身份选择提交失败：保留可选列表和错误说明，允许重试，不提前进入应用。
- 用户资料或身份加载失败：显示失败和重试入口，不将错误当作无身份。

## 需求

### 功能需求

- **FR-001**：系统必须支持唯一工号和密码登录；缺失输入、凭据错误和服务失败均有可理解的中文提示。
- **FR-002**：系统必须保存用户的工号、姓名、部门和选填头像；项目必须包含名称、城市、客户名称及项目类型，类型限定为商业地产、工业园区、住宅、政府项目。
- **FR-003**：系统必须支持同一用户关联多个项目及同项目多个角色，每个“用户 + 项目 + 角色”组合唯一；角色限定为质检员、施工方、管理员。
- **FR-004**：单身份自动进入；多身份必须先选择；零身份禁止进入。身份选项只能来自该账号已配置的有效关系。
- **FR-005**：当前登录必须且只能确定一个身份，切页和刷新保持身份；切换项目或角色只能退出后重新登录。
- **FR-006**：菜单、页面访问和资料读取必须以当前身份为准，不叠加其他身份权限；不能仅靠隐藏菜单防止越权。
- **FR-007**：每次受保护访问必须核实登录和当前身份有效性；客户端不能通过修改用户、项目或角色信息获得权限，普通用户不能自行修改角色关系或项目配置。
- **FR-008**：角色菜单必须遵守用户故事 3 的菜单矩阵；越权直链显示无权限提示和可访问页面入口，未选身份不得看到受保护内容。
- **FR-009**：应用必须具备宽屏侧栏、窄屏抽屉导航、当前菜单选中态、内容标题和身份区；退出入口在两类屏幕均可找到。
- **FR-010**：退出成功必须同时清除登录与当前身份；多身份账号重新登录必须重新选择。
- **FR-011**：登录、身份选择和页面加载必须有进行态；失败有重试或重新登录入口，不能将加载失败显示为成功或空结果。
- **FR-012**：登录页参考 Stitch 登录原型的居中表单、工号、密码和主要按钮；导航参考通用框架原型的侧栏、浅色分区、选中态和底部身份区。统一使用“建筑施工质检情报员”名称、中文界面、白底浅蓝和简约专业风格，不采用渐变、发光或堆叠阴影。原型与文字需求冲突时以文字需求为准。
- **FR-013**：本阶段必须提供各角色可访问的业务入口占位，明确说明尚未开放；默认进入助手，不提供模拟回答、业务统计或正式手动建单入口。
- **FR-014**：必须准备可重复使用的演示数据配置方式，包含两个明确标记为模拟的项目、三类角色、至少两名同项目施工方、三类单身份账号及覆盖同项目多角色和跨项目组合的多身份账号；演示说明与真实凭据分开管理，不将密码写入可提交文件。

### 关键实体

- **用户**：登录主体，具有唯一工号、姓名、部门和可选头像。
- **项目**：业务归属与权限边界，具有名称、城市、客户名称和类型。
- **项目角色关系**：将用户、项目和一个业务角色关联；一个用户可有多条关系。
- **当前登录身份**：本次有效登录中唯一选定的项目角色关系；随退出或登录失效清除，不能由用户自行扩权。

## 成功标准

### 可衡量结果

- **SC-001**：三类单身份演示账号均可用正确工号和密码直接进入默认页面；错误凭据均被拒绝且显示中文原因。
- **SC-002**：多身份账号覆盖至少两个项目和同项目两个角色；每次登录只进入一个选定身份，未选择时全部业务入口均不可进入。
- **SC-003**：三类角色的菜单与规定矩阵完全一致；直接访问其他角色页面、伪造身份和跨项目身份的走查全部被拒绝。
- **SC-004**：在 390 像素与 1440 像素宽度下，登录、身份选择、菜单导航、身份展示和退出均可完成，核心控件不被裁切；窄屏菜单三种关闭方式全部有效。
- **SC-005**：连续完成两次“登录 → 选择身份 → 切页或刷新 → 退出 → 重登选择其他身份”，展示始终与本次身份一致，退出后旧页面不能继续取得受保护内容。
- **SC-006**：全部阶段 1 业务入口准确标明未开放，无虚构业务结果；两套模拟项目及其账号关系可按说明重复准备，且不产生重复工号或重复身份。
