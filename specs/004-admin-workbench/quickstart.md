# 快速验收指南：阶段 4 管理员工作台

此指南在实现后执行；当前不表示功能已通过验收。

## 前置准备

1. 在项目根目录使用现有依赖，缺失时执行 `npm ci`；按 `.env.example` 准备本地连接环境，不输出或提交密钥。
2. 实施前核实云项目 architecture-intelligence（lvwlxhgsixyrcpdnbgpg）的表、函数、权限及已应用迁移；补查Supabase变更记录，再按计划应用新增只读RPC迁移。
3. 必要时运行 `npm run seed:demo` 准备模拟数据。此命令会写入演示账号及数据，仅在需要准备时执行，不在验收过程中反复重置。凭据仅查看忽略的 `.local/demo-accounts.json`，工单清单见 `.local/demo-work-orders.json`。
4. 执行 `npm run dev`，使用终端实际地址。准备当前项目管理员、另一项目管理员或对应身份、质检员、施工方及多身份账号。所需零值场景若缺失，在实施时补充明确模拟数据，勿清空既有项目。
5. 记录验收前真实工单状态和数量，按 [数据模型](data-model.md) 手工汇总基线，不依赖早期16张工单的固定分布。

## 核心路径

### A. 中心筛选与返回

- 导航进入 `/admin/work-orders`，五项均不限制，数量等于当前项目基线。
- 分别尝试三状态、四严重程度、三专业、关键词及完整编号；核对关键词涵盖描述、位置和详情。
- 验证两组以上组合交集、空白、前导#、非法编号、其他项目编号、包含 `%`、`_`、逗号的普通文本，以及不存在编号，不能错误扩大范围。
- 清空恢复全项目；打开长描述工单，核对完整内容；紧急突出，时间倒序和同时间编号排序稳定。
- 桌面打开抽屉并关闭、手机打开独立页并返回，原筛选不丢。刷新/直链和退出后重新登录的合法回跳也保留条件。
- 传入外部或非白名单 returnTo，须回退合法站内中心；普通角色详情行为不受影响。

### B. 大盘口径与联动

- 核对项目四项资料、总数和三状态；总数等于三状态之和。
- 核对待处理四风险；其和等于待处理数，紧急等于重点提示数；已结束紧急不参与风险统计。
- 数据不变时逐一验证 [契约](contracts/admin-workbench.md) 9 个指标入口，结果数量与指标一致，筛选项准确且无残留关键词。
- 验证零指标可点击、无紧急有明确提示；空项目所有指标显示0，正常显示项目信息，不能出现无意义百分比。

### C. 管理干预及刷新

- 分别完成编辑、解决、拒绝、同项目施工方指派、已结束重开；核对必填校验、状态、责任人及历史记录，不重复验收阶段3所有图片边界。
- 在待处理条件下解决最后一条匹配工单，详情仍保持打开，列表数量归零；关闭后出现空结果。
- 在详情完成操作后重新进入/刷新大盘，核对总数不变、状态和风险变化；重新打开已完成工单后再次核对。
- 制造一次版本冲突和一次读取或提交失败，确认错误清晰、输入保留、可重试，读取失败不显示假的0。

### D. 权限及响应式

- 质检员和施工方不见管理菜单，直达两个页面无权限；以真实会话直接调用两个新RPC也不能读管理员数据。
- 同账号当前为普通身份时不叠加管理员权限；未选身份不能读，退出后旧会话不能继续读。
- 两项目相同筛选分别核对，另一项目编号不能读取，详情/图片/操作也不越权。
- 在1440px与390px完成A～C核心交互，核对全部字段及筛选入口可用；一次点击完成指标下钻，管理员1分钟内能辨认待处理及紧急规模。
