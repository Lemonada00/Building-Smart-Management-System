# 功能规范：部署公网演示并完成全流程验收

**工作分支**：`master`  
**创建日期**：2026-11-17  
**状态**：可实施  
**输入**：按照原型和文档完成第 7 阶段开发。

## 用户场景与验收

### 用户故事 1：三种身份完成工单闭环（P1）

演示人员通过公网登录，按质检员、施工方和管理员身份完成同一张模拟工单的流转。

**优先理由**：这条路径贯穿助手咨询、现场报事、协同处理与管理监督。

**独立验收**：在桌面浏览器用预置账号登录。质检员取得可核对来源的规范答复，明确提出报事并确认草稿，施工方解决，质检员重开，管理员查看同一工单及大盘。

1. 工单在草稿确认后生成，记录显示创建、解决和重开的操作者及状态。管理员大盘与该项目工单清单一致。
2. 未取得规范依据时，助手明确说明，用户仍可主动按现场事实报事。

### 用户故事 2：在手机上查看和处理授权工单（P2）

用户可在手机完成登录、助手查询和草稿确认，也能打开授权的工单详情和现场照片。

**优先理由**：现场人员主要通过手机核对并处理问题。

**独立验收**：在 390px 与 1440px 宽度分别检查登录、助手、详情、编辑和管理员框架，对照项目 Stitch 原型和已验收界面。

1. 授权用户可由列表、助手结果或详情直链进入同一工单。
2. 工单转派后，原施工方重新请求详情或私有照片时失去访问权。退出后需要重新登录和选择身份。

### 边界场景

- 未选身份、跨项目身份或未分配的施工方访问受限资源时，应用拒绝访问。
- 咨询失败有明确提示。确认重复触发时只存在一张正式工单。
- 大盘对无工单的演示项目显示零值。

## 需求

### 功能需求

- **FR-001** 交付一个公网演示入口，支持预置账号登录和当前身份选择。
- **FR-002** 使用清楚标记的模拟项目、账号、工单与照片，演示说明与登录凭据分开管理。
- **FR-003** 助手可对真实知识服务执行文字及图文咨询。回答能核对来源，服务失败时给出明确提示。
- **FR-004** 支持在同一张工单上验证确认建单、施工方解决、质检员重开及管理员查看，处理记录和大盘反映实际状态。
- **FR-005** 线上按角色、项目和分配关系控制工单及私有照片访问。退出及转派后按最新权限处理详情直链。
- **FR-006** 记录部署版本、演示入口、操作步骤、实际结果和限制。

### 关键实体

- **演示身份**：预置账号、项目及当前角色。
- **模拟工单**：问题描述、专业、程度、位置、责任人、照片及处理记录。
- **演示版本**：公网入口对应的发布记录和可核对的源代码版本。

## 成功标准

### 可衡量结果

- **SC-001** 从公网入口完成至少一张模拟工单的咨询、确认、解决、重开及管理员查看，核对三次动作各自的记录。
- **SC-002** 至少一条文字和一条图文知识答复可核对来源，并验证一次知识服务失败后的提示。
- **SC-003** 390px 与 1440px 两种布局均可完成核心交互，匿名、跨项目、被转派及退出后的限制场景逐一验证。
- **SC-004** 演示记录包含一个可访问入口、一个可识别版本及三类身份的演示步骤。
