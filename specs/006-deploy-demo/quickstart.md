# 运行前准备

从仓库根目录执行命令。新环境先执行 npm ci，按 .env.example 配置本地变量。执行 npm run check 和 npm run build；复现历史 Turbopack 故障时执行 npm run build -- --webpack 并记录结果。构建后执行 npm start，通过本地服务验证登录和匿名详情拦截。

实施时重新查询 Supabase 项目和 Netlify 团队权限，按需执行 npm run seed:demo 补齐模拟数据。确认 Coze 可返回来源、图片平台适配通过，再记录候选部署 URL、提交与部署 ID。云端 Production 环境变量通过平台配置。

## 图片传输核验

用接近 10 MiB 的 JPEG、PNG、WebP 分别验证聊天上传、草稿选图和私有正式图片读取，同时验证超限拒绝。检查匿名、跨会话及转派后请求失败，退出清理临时照片后正式图片仍按权限可读。完整契约见 contracts/deployment.md，实体规则见 data-model.md。

# 演示与验收步骤

演示人员从验收记录取得公网登录地址。密码通过单独渠道获取，本地维护人员使用忽略的 `.local/demo-accounts.json`。三个角色选择同一个模拟项目。

1. 质检员登录后选择身份。在助手中向真实知识服务咨询施工规范，记录来源与条款。用模拟现场图片再做一次图文咨询，核对图中事实和引用。
2. 明确提出报事。核对问题、位置、程度、专业与施工方，选择模拟图片后确认。记录工单编号并核对创建记录与正式附件。重复确认仍返回同一编号。
3. 施工方登录后查找该编号，读取私有附件，填写处理说明并解决。
4. 质检员重新登录，核对处理记录、填写重开理由并重开。
5. 管理员以同一项目身份打开工单和大盘，对照处理记录和统计。选择无工单项目验证零值。
6. 在 390px 与 1440px 核对原型核心页面、详情直链和图片。分别以未登录、未选身份、跨项目以及被转派的原施工方重访详情和照片。确认退出后需重新选择身份。
7. 验证知识失败提示与主动按现场事实报事，记录实际结果及部署版本。使用模拟数据，验收记录只保留必要证据。
