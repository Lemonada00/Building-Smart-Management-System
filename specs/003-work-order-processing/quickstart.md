## 运行

在项目根目录执行：

```powershell
npm run dev
```

打开 http://127.0.0.1:3000/login。普通角色从工单列表进入；管理员通过本项目已知工单编号直链进入详情，本阶段不依赖管理员中心。

静态检查：

```powershell
npm run check
```

不默认构建、部署或添加自动化测试。接口和字段以 [契约](contracts/processing-contract.md)、[数据模型](data-model.md) 为准。

## 核心走查

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 解决→重开→再解决 | 施工方提交归因 A/建议 A；质检员填原因重开；施工方提交归因 B，不填建议 | completed→pending→completed；重开后当前结果清空；最后建议为空；记录分别保留 A、B 和重开原因 |
| 拒绝→重开→再处理 | 施工方拒绝填写原因；质检员重开；施工方再次处理 | 每次一条记录，原拒绝原因可回看，责任人不变 |
| 转派 | 施工方甲选择同项目乙并填写原因 | pending 不变；记录含甲→乙；甲收到成功提示并退出详情；乙能继续处理 |
| 原链接失权 | 转派前保存甲的详情链接、同源图片地址及旧表单 | 转派后甲新详情/图片请求及旧写入全部拒绝，发起人和管理员仍能查看 |
| 图片签名旁路 | 有权时用用户 SDK 尝试生成私有照片签名地址，再测试普通认证下载 | 下载成功，签名生成拒绝；不能在失权前预先取得可复用签名地址 |
| 退出后的请求 | 保存旧用户 JWT，退出登录后再请求详情、图片、上传、命令 | 真实 session 已撤销，不能仅因 JWT 尚未到期就继续读写 |
| 编辑保存 | 修改六类允许字段，上传两张照片、移除一张，保存后刷新 | 新内容和有序照片保存，状态/责任人不变，只有一条 edited 记录含字段和照片变化 |
| 编辑取消 | 同样修改文字/照片但取消 | 已保存内容和图片仍在，不加记录，新暂存不出现在详情 |
| 无修改 | 进入编辑直接保存 | 提示无修改，不增版本、不加记录 |
| 必填校验 | 空白归因/原因、缺枚举、无候选提交 | 提示对应字段，工单和记录不变 |
| 候选约束 | 提交当前责任人、跨项目、非施工方或停用成员 UUID | 均拒绝；无其他施工方时显示明确空候选说明 |
| 状态矩阵 | 三类角色分别查看 pending/completed/rejected 并尝试各操作 | 完全符合规范操作矩阵；隐藏按钮之外直接请求也拒绝 |
| 多身份 | 同用户退出后分别以施工方、质检员登录 | 权限只按本会话身份；施工方不能借发起人关系重开 |
| 管理干预 | 管理员通过直链编辑、解决、重开、指派 | 当前项目按规则可操作；其他项目拒绝 |
| 列表更新 | 默认 pending 下解决工单；改变严重程度；转派 | 已结束条目移出、紧急顺序正确、原责任人列表移除；筛选和排序保留 |

## 失败与并发走查

1. 编辑文字并选择两张照片，令其中一张上传失败：显示具体失败文件；文字、本地 File、其他成功暂存保留；不能保存成缺少照片的“成功”。恢复网络后重传并保存。
2. 在命令提交前断网或制造数据库校验失败：输入保留，不出现部分字段/照片提交。恢复后用原版本重试；结果不确定时先查最新记录确认，不自动换版本重放。
3. 两个有效会话同时打开同一版本，一个先编辑，另一个提交旧编辑/处理：后者冲突且保留输入，无覆盖。重读并人工核对后才能以新版本再次提交。
4. 连续点击保存或发送两次同版本命令：最多一次变更、一条记录；冲突不能显示第二次成功。
5. 其他会话转派或处理后，旧编辑会话尝试上传、保存：失权/状态变化拒绝；原已关联图片仍有效，未保存照片不出现。
6. 非图片、MIME 不匹配、超过 10 MiB、超过 9 张、混入他人工单照片 ID：均拒绝，不改变正式工单。核验绕过界面的直接请求也受约束。
7. 删除图片保存后，再以有权用户打开旧图片 URL：404；历史仍显示删除的标识/名称。清理暂未执行时文件也不得被下载。
8. 取消请求或离线清理失败：业务仍保持正确，记录清理限制即可，不把已成功编辑回报失败。
