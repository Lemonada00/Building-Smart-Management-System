# 分阶段开发与上线规划

确认日期：2026-10-27。

## 目标与已确认决策

- 交付可公网访问的完整 MVP 演示版，使用预置账号和模拟业务数据。
- 应用部署到 Vercel，沿用现有 Supabase 项目 `lvwlxhgsixyrcpdnbgpg`。
- 模型服务与既有 Coze 接口资料暂未准备好，先推进基础与工单阶段。
- 功能范围以 `doc/建筑施工质检情报员规格文档.md` 为准，遵循项目宪章与 AGENTS.md。
- 本文是路线规划，不代表已生成各阶段 SDD 文档或已实现业务功能。

## 阶段与验收

每阶段对应一个独立 Spec Kit SDD 单元。阶段开始时生成该阶段的 spec.md、plan.md、tasks.md；完成核心路径人工走查和 `npm run check` 后交付。阶段之间依赖已有能力，不重复建设。

| 阶段 | 功能边界 | 核心验收结果 | 有效 AI Coding 时间粗估 |
| --- | --- | --- | --- |
| 1. 应用框架与登录身份 | 登录页、响应式导航、退出、单身份直入、多身份选择；用户、项目、角色关系及当前身份权限基础；预置账号 | 三类角色菜单正确，多身份权限不叠加，越权页面被拦截，退出后可重新选择身份 | 2～3 小时 |
| 2. 工单数据与查询展示 | 工单与处理记录、数据权限、预置工单；普通列表、筛选排序、通用详情、宽屏抽屉与窄屏独立页面 | 质检员只看自己发起的，施工方只看当前负责的，跨项目隔离；紧急置顶、详情及历史记录正确 | 2～3 小时 |
| 3. 工单处理闭环 | 编辑、解决、拒绝、指派、重新打开；现场图片上传与权限；操作及处理记录一致保存 | 转派后原责任人失权；重新打开清空当前周期结果但保留历史；失败保留输入；可再次处理 | 2～4 小时 |
| 4. 管理员工作台 | 管理员工单中心、组合筛选、数据大盘及指标跳转；复用详情与操作 | 只统计当前项目；指标与筛选结果一致；风险仅统计待处理工单；管理干预可完成 | 1～2 小时 |
| 5. 智能助手查询与知识问答 | 模型与既有 Coze 接入；图片理解、最近 6 轮上下文、工单查询、知识问答、意图追问与范围限制 | 查询遵守身份权限；专业回答基于 Coze 依据；接口失败不编造判断；切页面保留对话、退出清空 | 2～4 小时 |
| 6. 智能建单与完整对话闭环 | 建单意图、缺项追问、创建卡片、责任人选择、图片确认、提交写入及混合意图 | 四项信息齐全才出卡片；五项必填齐全且用户确认后才创建；成功只读、避免重复创建；施工方不能创建 | 2～4 小时 |
| 7. 部署上线与全流程验收 | Vercel 部署、线上环境与登录跳转、数据库和图片权限检查、模型及 Coze 配置、演示说明 | 公网走通登录、咨询、建单、施工方处理、质检员重开、管理员查看；电脑和手机核心路径可用 | 1～3 小时 |

整体粗估为 12～23 小时有效 AI Coding 时间、7 段主开发对话，包含每阶段需求细化、实现、走查与修复，不是传统团队人日承诺。不包含等待接口资料、账号开通、外部服务或域名配置的时间。阶段 3、5、6 的不确定性较高。

## 依赖与执行顺序

按 1 → 2 → 3 → 4 → 5 → 6 → 7 顺序推进。阶段 1～4 不依赖模型或 Coze 接口，可先独立完成。

阶段 1 的智能助手默认入口可展示明确的未开放说明，不能伪装成已接入的助手。阶段 2～4 通过预置工单验收，不增加正式手动建单入口，保留规格中“仅通过智能助手创建工单”的要求。

开始阶段 5 前，需要准备可用模型服务（包含图片理解能力）、服务端凭据，以及既有 Coze 接口的调用地址、认证方式、请求与返回示例及失败表现。凭据只配置在本地忽略文件和服务端环境变量中，不写入文档或提交仓库。具体 Agent 实现方案在阶段 5 规划时确定。

接口未就绪时，阶段 1～4 可交付并验收；不得将模拟助手视为阶段 5～6 完成，也不得将其视为完整 MVP 上线。

## 模拟数据

开发时自行创建两个明确标记为模拟的项目，准备质检员、管理员、至少两名可互相转派的施工方及多身份账号。模拟项目不替换现有 Supabase 云项目。

工单覆盖三种状态、四种严重程度、三类专业，以及图片、转派、拒绝、多次重新打开和历次处理结果。保留空列表、查询无结果和跨项目不可见场景。账号和项目关系按规格由系统外预置，不开发注册或成员管理页面。

## 本轮不扩展的范围

不增加历史工单知识库、自助注册、项目或成员管理、语音输入、自动化测试覆盖率、无障碍专项或与核心演示无关的生产化建设。保留现有规格要求的响应式界面、服务端权限验证与数据库最小权限约束。
