# 建筑智能

建筑智能是面向施工项目的质检工单 MVP。它把现场问题、位置、照片、当前责任人和整改记录集中到一张工单，帮助质检员上报和复查、施工方处理和转派、项目管理员跟踪待处理风险。

公网模拟数据演示：[Netlify](https://architecture-intelligence.netlify.app) · [Vercel](https://architecture-intelligence-lemonada00.vercel.app)。体验需要演示账号。两站已发布并通过基础登录和授权读单走查。Coze 可核对来源的知识回答及相关公网全流程仍待验收。详见 [项目进度](./progress.md) 和 [部署验收](./specs/006-deploy-demo/verification.md)。

## 主要功能

| 功能 | 当前能力 |
| --- | --- |
| 登录与项目身份 | 工号和密码登录。多身份账号每次登录选择一个项目角色，退出重登可重选 |
| 工单查询 | 质检员查看本人发起的工单，施工方查看本人当前负责的工单，管理员在管理中心查看当前项目工单。列表和助手结果共用详情，宽屏打开抽屉，窄屏或直接访问链接时打开独立页面 |
| 整改闭环 | 按角色和状态编辑、解决、拒绝、转派或重开，保留处理历史。转派后原责任人失去访问权限，工单现场照片随工单权限读取 |
| 智能助手 | 接收文本和相册图片，通过 OpenRouter 理解现场线索并查找当前身份可读工单。质检员和管理员可编辑助手生成的草稿，选择责任人并确认建单 |
| 管理工作台 | 管理员可组合筛选工单、查看项目状态统计和待处理风险，点击指标下钻到对应明细 |
| 施工知识咨询 | 已接入 Coze 单轮查询。依据不足时给出提示，用户仍可明确选择按现场事实报事。有可核对来源的文字及图文回答待验收 |

## 安装方法

需要 Node.js 24.x、npm、Git，以及有账号和业务表的 Supabase 项目。在仓库根目录执行：

```powershell
npm ci
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

按 [环境变量模板](./.env.example) 填写 `.env.local`。

| 配置 | 用途 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 登录、会话和授权业务访问 |
| `SUPABASE_SECRET_KEY` | 准备模拟数据，以及鉴权后的服务端聊天图片上传与清理 |
| `OPENROUTER_BASE_URL`、`OPENROUTER_API_KEY`、`OPENROUTER_MODEL` | 助手模型调用。图文体验需选择支持图片输入的模型 |
| `COZE_BASE_URL`、`COZE_API_KEY`、`COZE_BOT_ID` | 知识咨询。使用已发布的智能体与具有 chat 权限的令牌 |

将密钥保存在 Git 忽略的 `.env.local` 中。OpenRouter、Coze 和 Supabase Secret Key 均仅在服务端使用。修改配置后重启开发服务。

沿用团队现有 Supabase 项目时，向项目维护者获取连接配置和演示账号。使用空数据库时，先按文件名顺序应用 [数据库迁移](./supabase/migrations/)，再在获授权的演示数据库中准备数据：

```powershell
npm run seed:demo
```

脚本可重复运行，复用既有账号与工单，不重置已有密码。首次生成的密码保存在本机被 Git 忽略的 `.local/demo-accounts.json`，按 `employeeId` 查找。已有账号的凭据从安全备份取得。

```powershell
npm run dev
```

打开 [本地登录页](http://localhost:3000/login)，使用工号和密码登录。可用 `npm run check` 执行 Biome 和 TypeScript 检查，或用 `npm run check:supabase` 检查 Supabase Auth HTTP 连接。

## 使用方法

1. **质检员上报**。例如使用 `qc001` 登录，打开智能助手，明确说明要建工单，提供问题描述、详细位置、严重程度和专业类型。缺项时按提示补充。核对草稿、选择当前项目的施工方并确认。可按需保留现场图片。
2. **施工方处置**。例如使用 `sg001` 登录，从工单列表打开本人负责的待处理工单。选择解决并填写问题归因，或说明原因后拒绝。需要转派时，选择当前项目内另一名施工方并填写原因。
3. **发起人复查**。从工单详情查看处理结果。需要继续整改时，对已完成或已拒绝的工单填写原因并重开，历次处理记录可回看。
4. **管理员跟进**。例如使用 `admin001` 登录，在数据大盘点击待处理紧急工单指标进入预筛选的工单中心，再打开相应详情查看责任人和处理记录。

`multi001` 可用于体验多身份选择。同一会话始终使用选定的项目和角色权限。聊天图片与工单现场照片的可见范围不同，聊天图片持有链接即可读取，演示时请使用模拟素材。

## 输入输出示例

示例描述界面行为。助手措辞、实际编号和工单状态取决于当次输入及已有数据。

| 场景 | 示例输入或操作 | 界面输出 |
| --- | --- | --- |
| 查工单 | 在智能助手输入「查一下 #2017」 | 若已存在该单且当前身份可读，显示含编号、状态、严重程度、位置和责任人的结果卡，可打开详情。新准备的基础演示数据可改查 `.local/demo-work-orders.json` 中当前身份可读的编号 |
| 建工单 | 质检员输入「帮我建工单：1 号楼 2 层东侧墙面有裂缝，严重程度一般，专业土建」 | 助手整理草稿。选择当前项目的施工方并确认后，出现正式工单编号，状态为「待处理」，新增创建记录。若缺具体位置等必填信息，助手先追问 |
| 解决工单 | 当前施工方打开待处理单，点击「解决」，填写归因「基层处理不到位」 | 状态更新为「已完成」，处理记录显示本次操作及归因 |
| 知识依据不足 | 输入「请查找混凝土墙面裂缝验收的条文依据」 | 若知识服务未提供可用依据，助手提示无法给出有依据的判断。用户可明确提出按已记录的现场事实建单 |
